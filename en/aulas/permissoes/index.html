Lesson 4 · 20 min

Permissions per step: capabilities and policy

Plan only reads. Execute edits the code and runs the tests. Review reads and runs the tests. If all three steps run with the same permission, the whole loop has the permission of the most dangerous one. In this lesson each step gets its own settings.json in Claude Code and its own -s in Codex, and you see where a deny rule lets things through.

Start the lesson

In this lesson you will

  1. 1deny, then ask, then allow: the fixed order from the docs
  2. 2Why Bash(rm -rf *) doesn't catch rm -r -f
  3. 3One settings.json per step and the right -s in Codex
  4. 4A cap per type of action: the inema-agent-runtime policy

Goal: give each step of the loop only the permissions it uses, with deny in the settings.json of Claude Code and -s in Codex.

02 · The cap on each action

From the POLITICA.md of inema-agent-runtime (10/05/2026), summarized.

1. Read: N4

Read a file, page or spreadsheet: the agent does it on its own, with no notice. In Claude Code, allowed; in Codex, -s read-only.

2. Change: N3

Create or change a project file: it does it on its own and tells you. In Claude Code, acceptEdits; in Codex, -s workspace-write.

3. Send and system: N2

A command that changes the system, and sending (email, message, post, push): it runs after asking, every single time. In Codex, no auto-approval.

4. Spend and delete: N1

Spending credit and deleting data or production: the agent only prepares it, the human executes it (and with a backup). In the loop, this becomes the gate from lesson 7.

Same scale, different nameThe agents' constitution (INEMA) uses 3 does it on its own, 2 does it and tells you, 1 proposes, 0 does not touch.

03 · The settings.json for the execute step

Rules in the format of the current docs: Bash(rm *) matches rm and rm with any argument. Edit and Read paths follow the gitignore pattern.

File · kit/permissoes/executar.json
{
  "permissions": {
    "allow": [
      "Edit(src/**)",
      "Bash(python3 -m pytest *)",
      "Bash(git status *)",
      "Bash(git diff *)"
    ],
    "ask": [
      "Bash(git commit *)"
    ],
    "deny": [
      "Bash(rm *)",
      "Bash(git push *)",
      "Bash(git reset *)",
      "Bash(git clean *)",
      "Bash(curl *)",
      "Bash(wget *)",
      "WebFetch",
      "Edit(tests/**)",
      "Edit(goal.md)",
      "Edit(.claude/**)",
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(~/.ssh/**)"
    ]
  }
}
Template · one line per step (Claude Code and Codex)
K=~/projetos/loop-r-eng-seguranca-v72/kit/permissoes
# planejar: só lê
claude -p --settings $K/planejar.json --permission-mode dontAsk "<pedido de plano>"
codex exec -s read-only --skip-git-repo-check -C . - < plano.md
# executar: edita no projeto, sem rede
claude -p --settings $K/executar.json --permission-mode dontAsk "<pedido>"
codex exec -s workspace-write --skip-git-repo-check -C . - < prompt.md
# revisar: lê e roda os testes
claude -p --settings $K/revisar.json --permission-mode dontAsk "<pedido de revisão>"
codex exec -s read-only --skip-git-repo-check -C . - < revisar.md

04 · Rehearsal: which rule decides each command

regra.py imitates, in simplified form, what the docs describe (order, subcommands, $( ), the trailing *). The one that really decides is Claude Code.

Terminal · narrow deny and right deny
K=~/projetos/loop-r-eng-seguranca-v72/kit/permissoes
echo "## deny só com Bash(rm -rf *)"
for c in "rm -rf build" "rm -r -f build" "git push -f origin main"; do
  python3 $K/regra.py $K/so-rm-rf.json "$c"; echo "  saída: $?"
done
echo "## executar.json"
for c in "python3 -m pytest -q" "cd /tmp && rm -rf build" "rm -r -f build" \
         'echo $(curl -s https://exemplo.invalid)' "git commit -m x" "ls"; do
  python3 $K/regra.py $K/executar.json "$c"; echo "  saída: $?"
done
Example from the repository
## deny só com Bash(rm -rf *)
deny      Bash(rm -rf *)         ← rm -rf build
  saída: 1
sem regra -                      ← rm -r -f build
  saída: 4
sem regra -                      ← git push -f origin main
  saída: 4
## executar.json
allow     Bash(python3 -m pytest *) ← python3 -m pytest -q
  saída: 0
deny      Bash(rm *)             ← rm -rf build
  saída: 1
deny      Bash(rm *)             ← rm -r -f build
  saída: 1
deny      Bash(curl *)           ← curl -s https://exemplo.invalid
  saída: 1
ask       Bash(git commit *)     ← git commit -m x
  saída: 3
sem regra -                      ← ls
  saída: 4

With only Bash(rm -rf *), the same delete written as rm -r -f matches no rule. Bash(rm *) catches both forms, and the curl inside $( ) is blocked too. "sem regra" becomes a question in the terminal; in the loop, with --permission-mode dontAsk, it becomes a refusal (docs).

A Bash rule matches text. find build -delete, a script that deletes inside, or python3 -c with shutil do not start with rm. For those, lesson 5 adds a hook, and lesson 6 a sandbox, which reads no text at all.

05 · Real: deny holds even in the mode that allows everything

One call to Claude Code with --permission-mode bypassPermissions and executar.json. The request is to run rm -rf build. You check the disk, not the answer.

Terminal · one real call
bash ~/projetos/loop-r-eng-seguranca-v72/kit/permissoes/real.sh; echo "saída: $?"
Example from the repository
build/app.bin continua lá: deny segurou (código do claude: 0)
saída: 0
Falhou: `rm -rf build` não rodou, porque a permissão do Bash para esse comando foi negada. A pasta `build/` (com `app.bin`) continua lá. Não tentei de novo nem apaguei a pasta de outro jeito.

One round, Claude Code 2.1.303. The "Falhou:" at the start comes from a rule in this machine's global CLAUDE.md (announce when processing ends), not from Claude Code. What counts is the line on disk: build/app.bin is still there.

E11 · Your Codex's default sandbox

5 min

Check whether your config.toml turns the sandbox off for all calls. On this machine it was set to danger-full-access, put there when bubblewrap was failing; since then, every codex exec in the loop needs an explicit -s.

Done when: grep -n sandbox_mode ~/.codex/config.toml prints nothing or prints read-only/workspace-write; if it prints danger-full-access, every codex exec in your loop takes -s.

08 · In three sentences

Each step, its ownPlanning and reviewing do not edit; executing edits only where it needs to.
deny always winsdeny → ask → allow, and subcommand counts. Write Bash(rm *), not just rm -rf.
explicit -sIn Codex, the sandbox goes on the loop line, not in the hope of the config.
