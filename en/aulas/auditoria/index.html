Lesson 8 · 20 min

Security audit of your loop

Everything the course built fits in one file: the map of your loop's sessions, with each session's tools and controls. auditar.py reads the map, checks the trifecta, the Rule of Two, permissions, guard, proven isolation, network, gate and caps, and writes the checklist of what's missing. You fix it, audit again and set the next review.

Start the lesson

In this lesson you will

  1. 1The full map: tools and controls per session
  2. 2Eight items per session, each with the lesson that fixes it
  3. 3The checklist in Markdown, generated and versioned in the project
  4. 4Re-audit: with every new tool, every new machine

Goal: audit your loop with the session map, generate the checklist of what's missing and set the date of the next review.

## corretor
  FALHA tríade letal → corte uma perna: leitor sem dados nem saída que devolve só campos (aula 1)
  FALHA Regra de Dois → no máximo 2 de A/B/C por sessão, ou nova sessão de contexto limpo, ou humano (aula 2)
  FALHA permissões (deny mínimo) → acrescente ao deny: rm, push, rede, env (kit/permissoes/executar.json, aula 4)
  FALHA hook de guarda → ligue a guarda.py em PreToolUse (aula 5)
  FALHA isolamento provado → rode o prova-isolamento.sh com o mesmo wrapper do loop e anote a data (aula 6)
  FALHA rede x dados privados → sessão que lê dado privado roda sem rede (aula 6)
  FALHA irreversível pede humano → envio, push e apagar passam pela porta.py (aula 7)
  FALHA tetos de tempo e memória → timeout + MemoryMax em cada ciclo (aula 7; curso 2, aula 6)

The safe map has three sessions (reader, fixer, publish) and passes all 22 items. The publish session combines all three legs, but with a human on every action.

Setting "rede": false without having run prova-isolamento.sh, or "porta": true while a send is still direct in the code, makes the audit approve an open loop. Every control in the map needs a proof from the earlier lessons next to it.
